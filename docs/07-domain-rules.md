# 07. 핵심 도메인 규칙

## 목적

화면은 바뀌어도 가격, 재고, 주문 상태 같은 비즈니스 규칙은 일관되어야 합니다. 이 문서는 이후 데이터 모델과 서버 로직의 기준이 됩니다.

## 가격

- 모든 원화 금액은 원 단위 정수로 저장합니다.
- `판매가`는 0보다 커야 하고 `정가`를 초과할 수 없습니다.
- 할인율은 저장값이 아니라 정가와 판매가로 계산해 표시합니다.
- 장바구니 금액은 예상값이며 주문 생성 시 서버가 최신 가격으로 다시 계산합니다.
- 주문에는 주문 당시 상품명, 옵션명, 단가를 스냅샷으로 보관합니다.

## 상품과 옵션

- 상품은 `DRAFT`, `ACTIVE`, `SOLD_OUT`, `ARCHIVED` 중 하나의 판매 상태를 가집니다.
- 실제 구매 가능 여부는 상품 상태와 선택 옵션 재고를 모두 확인해 결정합니다.
- 색상·사이즈 조합은 하나의 구매 옵션이며 고유 SKU를 가집니다.
- 주문에 사용된 상품과 옵션은 물리 삭제하지 않고 보관 또는 비활성화합니다.

## 재고

- 재고는 옵션별 0 이상의 정수입니다.
- 주문 생성 직전에 서버가 재고를 다시 확인합니다.
- 주문 생성과 재고 차감은 같은 데이터베이스 트랜잭션에서 처리합니다.
- 동시에 주문이 들어와도 재고가 음수가 되면 안 됩니다.
- 주문 취소 시 재고 복구는 취소 처리와 같은 트랜잭션에서 정확히 한 번만 수행합니다.
- 관리자 재고 변경은 변경 전후 값, 사유, 수행자, 시간을 기록합니다.

## 장바구니

- 장바구니 항목은 상품이 아니라 구매 옵션과 수량을 참조합니다.
- 같은 옵션을 다시 담으면 별도 행을 만들지 않고 수량을 합칩니다.
- 화면에 표시하기 전 가격·판매 상태·재고를 최신 데이터와 비교합니다.
- 품절 상품은 자동 삭제하지 않고 문제 상태와 수정 행동을 보여줍니다.
- Guest 장바구니를 로그인 후 Member 장바구니와 합칠 때 동일 옵션은 수량을 합치되 재고를 넘지 않습니다.

## 주문

### 상태

```text
PENDING_PAYMENT → PAID → PREPARING → SHIPPED → DELIVERED
        │           │        │
        └───────────┴────────┴──→ CANCELLED (출고 전 정책에 한함)
```

- 상태 변경은 위에서 허용한 방향으로만 수행합니다.
- `SHIPPED` 이후 취소는 MVP에서 지원하지 않습니다.
- 주문 번호는 외부에 노출 가능한 별도 식별자를 사용하며 DB 순번을 그대로 노출하지 않습니다.
- 주문 요청에는 멱등성 키를 사용해 중복 생성과 중복 재고 차감을 방지합니다.
- 주문 합계는 상품 합계, 할인, 배송비, 최종 결제 금액으로 분리해 저장합니다.

## 인증과 권한

- 인증은 사용자가 누구인지 확인하고, 인가는 해당 행동을 할 수 있는지 확인합니다.
- 화면에서 버튼을 숨기는 것만으로 권한을 보호하지 않고 모든 관리자 요청을 서버에서 검사합니다.
- Member는 자신의 찜, 장바구니, 배송지, 주문만 조회·변경할 수 있습니다.
- 공개 오류 응답은 다른 사용자의 데이터 존재 여부를 추측할 수 없게 합니다.

## 기록과 개인정보

- 주문과 재고처럼 중요한 변경은 누가, 언제, 무엇을 바꿨는지 기록합니다.
- 로그에는 비밀번호, 인증 토큰, 전체 주소와 같은 민감 정보를 남기지 않습니다.
- 데모 계정과 데이터는 실제 개인정보와 분리합니다.

## 오류 분류

| 종류 | 예시 | 사용자 처리 |
| --- | --- | --- |
| 입력 오류 | 필수 배송지 누락 | 해당 입력란에서 수정 안내 |
| 도메인 충돌 | 재고 부족, 가격 변경 | 이유와 가능한 다음 행동 안내 |
| 권한 오류 | 타인의 주문 접근 | 상세 정보 없이 접근 거부 |
| 시스템 오류 | DB·네트워크 장애 | 재시도 안내와 오류 추적 ID 제공 |
