# 17. 고객용 MVP 구현

## 결과

7단계에서 `상품 발견 → 옵션 선택 → 장바구니 → 로그인 → 배송지 입력 → 테스트 주문 → 주문 조회`를 하나의 실제 데이터 흐름으로 연결했습니다. 결제는 포트폴리오 전용 테스트 처리이며 카드 정보나 실제 결제사 키를 사용하지 않습니다.

## 구현 범위

| 영역 | URL | 핵심 동작 |
| --- | --- | --- |
| 홈 | `/` | DB의 최신 상품과 7단계 상태 표시 |
| 카탈로그 | `/products` | 검색, 브랜드·카테고리·사이즈·가격 필터, 가격·신상품 정렬 |
| 상품 상세 | `/products/[slug]` | 이미지, 가격, 소재, 배송, 옵션별 재고, 장바구니 담기 |
| 인증 | `/signup`, `/login` | 이메일 가입·로그인, 내부 경로만 허용하는 복귀 URL |
| 장바구니 | `/cart` | 비회원 30일 쿠키, 회원 장바구니 병합, 수량·삭제·가격 변경 표시 |
| 주문 | `/checkout` | 로그인 보호, 배송지 검증, 테스트 결제와 재고 차감 |
| 주문 확인 | `/orders/[orderNo]/complete` | 생성된 주문번호와 금액 확인 |
| 내 주문 | `/account/orders`, `/account/orders/[orderNo]` | 로그인한 본인의 주문만 목록·상세 조회 |

## 주문 트랜잭션

```text
세션과 입력 검증
→ 사용자별 idempotency key 중복 확인
→ 장바구니 상품의 현재 판매 상태·가격·재고 조회
→ 합계와 배송비를 서버에서 재계산
→ 주문·주소·품목 snapshot·테스트 결제 이력 생성
→ version과 현재 재고 조건으로 옵션 재고 차감
→ 재고 감사 로그 생성
→ 장바구니 비우기
```

전체 작업은 PostgreSQL `Serializable` 트랜잭션에서 실행됩니다. 중간에 한 옵션이라도 재고가 바뀌면 전체 주문을 취소하고 사용자에게 다시 확인하도록 안내합니다.

## 비회원 장바구니 보호

브라우저에는 추측하기 어려운 임의 토큰만 `HttpOnly`, `SameSite=Lax` 쿠키로 저장합니다. DB에는 원문이 아닌 SHA-256 해시만 저장합니다. 로그인에 성공하면 비회원 품목을 회원 장바구니에 합치고 쿠키를 제거합니다.

## 포트폴리오에서 보여주는 역량

- Server Component 조회와 Server Action 변경 경계
- Prisma 관계 조회와 PostgreSQL 제약조건을 함께 사용한 무결성 보호
- Better Auth 기반 세션 인증과 주문 소유권 검사
- 반응형·키보드 접근 가능한 상태 UI
- 순수 가격 규칙의 단위 테스트와 실제 DB를 준비하는 CI 자동화
