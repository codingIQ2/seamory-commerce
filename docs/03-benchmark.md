# 03. 벤치마킹 원칙

## 목적

ZOZOTOWN과 무신사 같은 멀티브랜드 패션 플랫폼에서 **사용자 문제가 어떻게 해결되는지**를 학습합니다. 화면을 복제하거나 상표·콘텐츠를 사용하는 것이 목적은 아닙니다.

## 관찰할 영역

| 영역 | 관찰 질문 | HUKUPUKU 적용 방향 |
| --- | --- | --- |
| 홈 | 많은 콘텐츠에 우선순위를 어떻게 주는가? | 편집 컬렉션과 개인 탐색의 진입점을 분리 |
| 상품 목록 | 필터와 정렬을 얼마나 빠르게 조작할 수 있는가? | 모바일 우선 필터, 적용 조건을 칩으로 표시 |
| 상품 카드 | 비교에 꼭 필요한 정보는 무엇인가? | 브랜드, 상품명, 현재가, 할인, 찜, 품절 표시 |
| 상세 | 구매 불안을 어떤 정보로 줄이는가? | 옵션별 재고, 배송, 소재, 사이즈 정보를 구조화 |
| 장바구니 | 오류와 가격 변경을 어떻게 알리는가? | 서버 재검증 결과와 사용자의 다음 행동을 안내 |
| 마이페이지 | 주문 상태를 어떻게 이해시키는가? | 상태 타임라인과 주문별 상세 제공 |
| 관리자 | 반복 작업과 실수를 어떻게 줄이는가? | 일괄 작업보다 안전한 검증과 변경 이력을 우선 |

## 참고하되 복제하지 않는 것

- 참고: 탐색 패턴, 정보의 우선순위, 상태 표현, 모바일 상호작용
- 독자 설계: 브랜드, 카피, 색상, 컴포넌트 형태, 레이아웃 비율, 샘플 데이터
- 금지: 로고, 상품 사진, 설명 문구, 리뷰, CSS, 소스코드의 무단 사용

## 포트폴리오에서 보여줄 판단

1. 어떤 사용자 문제를 발견했는가
2. 여러 해결안 중 무엇을 선택했는가
3. 선택의 장단점은 무엇인가
4. 코드와 데이터 구조에 어떻게 반영했는가
5. 테스트나 지표로 어떻게 검증했는가

## 다음 단계 조사 항목

- 모바일·데스크톱 핵심 화면 캡처와 패턴 분류
- 상품 탐색에 필요한 필터 속성 목록
- 주문 상태와 재고 변경 규칙 비교
- 국내 전자상거래 표시 의무 및 개인정보 처리 요구사항 확인
