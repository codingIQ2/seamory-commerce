# 06. 사용자 시나리오와 인수 조건

## 작성 방식

사용자 스토리는 `누가 / 무엇을 / 왜`의 형식으로 목적을 설명합니다. 인수 조건은 개발 완료 여부를 판단할 수 있도록 `Given / When / Then`으로 작성합니다.

## US-01 상품 탐색과 검색

**스토리**  
Guest로서 원하는 분위기와 조건의 상품을 빠르게 찾고 싶다. 그래야 많은 상품을 하나씩 열지 않고 후보를 좁힐 수 있다.

**연결 요구사항**  
FR-CAT-01~06, FR-CAT-08

**인수 조건**

1. Given 판매 중인 상품이 존재할 때, When 사용자가 카테고리를 열면, Then 상품 카드와 전체 결과 수가 표시된다.
2. Given 검색어를 입력했을 때, When 검색을 실행하면, Then 상품명 또는 브랜드명이 일치하는 결과만 표시된다.
3. Given 여러 필터를 선택했을 때, When 적용하면, Then 모든 선택 조건을 만족하는 결과와 적용된 필터 칩이 표시된다.
4. Given 일치하는 상품이 없을 때, Then 빈 화면과 함께 필터 초기화 또는 다른 검색어 안내가 표시된다.
5. Given 필터가 적용된 목록에서 새로고침했을 때, Then URL을 통해 같은 조건이 복원된다.

## US-02 상품 옵션 선택

**스토리**  
구매자로서 상품의 가격, 소재, 사이즈와 재고를 한곳에서 확인하고 싶다. 그래야 구매 가능 여부를 확신하고 옵션을 선택할 수 있다.

**연결 요구사항**  
FR-CAT-05~06, FR-CART-01

**인수 조건**

1. Given 상품 상세에 진입했을 때, Then 현재 가격과 할인 정보, 이미지, 소재, 배송 안내가 표시된다.
2. Given 옵션별 재고가 다를 때, Then 품절 옵션은 선택할 수 없고 품절임이 텍스트로 전달된다.
3. Given 옵션을 선택하지 않았을 때, When 장바구니 담기를 누르면, Then 필요한 옵션과 오류 위치가 안내된다.
4. Given 판매 가능한 옵션과 수량을 선택했을 때, When 장바구니에 담으면, Then 담긴 상품과 수량이 확인된다.

## US-03 장바구니 검토

**스토리**  
구매자로서 주문 전 선택한 상품과 최종 예상 금액을 검토하고 싶다. 그래야 실수 없이 결제를 시작할 수 있다.

**연결 요구사항**  
FR-CART-02~05

**인수 조건**

1. Given 장바구니에 상품이 있을 때, Then 상품별 옵션·수량·금액과 전체 금액 구성이 표시된다.
2. Given 수량을 재고보다 크게 변경할 때, Then 변경이 거부되고 가능한 최대 수량이 안내된다.
3. Given 상품 가격 또는 판매 상태가 바뀌었을 때, When 장바구니를 다시 열면, Then 최신 상태와 변경 사실이 표시된다.
4. Given Guest가 브라우저를 닫았다 다시 열었을 때, Then 같은 브라우저에서 장바구니가 복원된다.

## US-04 테스트 주문 완료

**스토리**  
Member로서 배송지와 금액을 최종 확인하고 안전하게 테스트 주문을 완료하고 싶다.

**연결 요구사항**  
FR-AUTH-02~03, FR-ORDER-01~05, NFR-DATA-01, NFR-REL-01

**인수 조건**

1. Given Guest가 결제를 시작했을 때, Then 로그인 후 기존 장바구니로 돌아갈 수 있다.
2. Given 배송지 필수 항목이 비어 있을 때, When 주문을 시도하면, Then 주문은 생성되지 않고 항목별 오류가 표시된다.
3. Given 가격과 재고가 유효할 때, When 테스트 결제가 성공하면, Then 서버 계산 금액으로 주문이 한 번만 생성되고 재고가 차감된다.
4. Given 동일한 주문 요청이 다시 전달될 때, Then 새로운 주문이나 추가 재고 차감이 발생하지 않는다.
5. Given 주문이 완료되면, Then 주문 번호와 주문 상세로 이동할 수 있다.

## US-05 결제 직전 재고 충돌

**스토리**  
구매자로서 결제 직전에 재고가 없어졌다면 정확한 이유를 알고 장바구니를 수정하고 싶다.

**연결 요구사항**  
FR-CART-04, FR-ORDER-02~04

**인수 조건**

1. Given 다른 주문으로 선택 옵션의 재고가 부족해졌을 때, When 결제를 시도하면, Then 주문과 재고 차감이 모두 취소된다.
2. Then 부족한 옵션과 구매 가능한 수량이 표시된다.
3. Then 사용자는 장바구니로 돌아가 수량 또는 옵션을 수정할 수 있다.

## US-06 내 주문 확인

**스토리**  
Member로서 내가 주문한 상품과 처리 상태를 확인하고 싶다.

**연결 요구사항**  
FR-ORDER-05~07

**인수 조건**

1. Given 로그인한 Member가 주문 목록을 열면, Then 본인의 주문만 최신순으로 표시된다.
2. Given 주문 상세를 열면, Then 주문 시점의 상품명·옵션·가격·배송지와 현재 상태가 표시된다.
3. Given 출고 전 취소 가능한 상태라면, When 취소를 확인하면, Then 주문이 취소되고 재고가 한 번만 복구된다.
4. Given 다른 사용자의 주문 주소로 접근하면, Then 존재 여부를 노출하지 않고 접근이 거부된다.

## US-07 관리자 상품과 재고 관리

**스토리**  
Admin으로서 상품, 옵션, 판매 상태와 재고를 정확하게 관리하고 싶다.

**연결 요구사항**  
FR-AUTH-03~04, FR-ADMIN-01~02, FR-ADMIN-04~05

**인수 조건**

1. Given Admin이 유효한 상품 정보를 저장하면, Then 상품과 옵션이 생성되고 고객 화면에 판매 상태대로 반영된다.
2. Given 필수 정보나 가격 형식이 잘못되면, Then 저장되지 않고 수정할 항목이 안내된다.
3. Given 재고를 변경하면, Then 변경 전후 값, 수행자, 시간이 기록된다.
4. Given 일반 Member가 관리자 주소나 API에 접근하면, Then 서버가 요청을 거부한다.

## US-08 관리자 주문 처리

**스토리**  
Admin으로서 주문을 확인하고 허용된 순서에 따라 처리 상태를 갱신하고 싶다.

**연결 요구사항**  
FR-ADMIN-03~05

**인수 조건**

1. Given Admin이 주문 목록을 열면, Then 상태와 기간으로 주문을 찾을 수 있다.
2. Given 결제 완료 주문을 준비 중으로 변경하면, Then 고객의 주문 상세에도 같은 상태가 반영된다.
3. Given 현재 상태에서 허용되지 않는 상태로 변경하면, Then 서버가 거부하고 주문은 기존 상태를 유지한다.
4. Given 상태가 변경되면, Then 이전 상태, 새 상태, 수행자, 시간이 기록된다.

## 대표 데모 시나리오

포트폴리오 시연에서는 아래 하나의 흐름으로 고객과 관리자 기능의 연결을 보여줍니다.

```text
검색과 필터 → 상품 옵션 선택 → 장바구니 → 테스트 주문
→ 관리자 주문 처리 → 고객 주문 상태 확인
```
