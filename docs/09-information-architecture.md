# 09. 정보 구조와 탐색 체계

## 문서 목적

HUKUPUKU의 고객·회원·관리자 영역을 나누고, 사용자가 어디에서 무엇을 찾는지와 화면 사이의 이동 규칙을 정의합니다. 이 구조는 다음 단계의 와이어프레임, Next.js 라우팅, 접근 권한 설계의 공통 기준입니다.

## 설계 원칙

1. **발견에서 구매까지 끊기지 않게 한다.** 목록, 상세, 장바구니, 체크아웃의 주 행동을 한 단계씩 연결합니다.
2. **현재 탐색 조건을 잃지 않게 한다.** 검색어·필터·정렬·페이지는 URL에 기록해 새로고침과 공유 후에도 복원합니다.
3. **고객과 운영자의 문맥을 분리한다.** 고객 영역과 `/admin` 영역은 내비게이션과 권한 경계를 명확히 나눕니다.
4. **모바일에서도 같은 과업을 제공한다.** 메뉴 배치는 달라도 상품 탐색과 구매 기능을 제거하지 않습니다.
5. **상태를 화면의 일부로 설계한다.** 로딩, 빈 결과, 입력 오류, 재고 충돌, 접근 거부를 정상 화면과 함께 정의합니다.

## 서비스 영역

| 영역 | 주요 사용자 | 목적 | 대표 진입점 |
| --- | --- | --- | --- |
| 발견 | Guest, Member | 상품과 브랜드를 탐색하고 후보를 좁힘 | `/`, `/products` |
| 구매 | Guest, Member | 옵션을 선택하고 장바구니와 주문을 완료함 | `/products/[slug]`, `/cart`, `/checkout` |
| 계정 | Member | 프로필과 자신의 주문을 확인함 | `/account/orders` |
| 운영 | Admin | 상품·옵션·재고·주문을 관리함 | `/admin/products`, `/admin/orders` |

## 사이트맵

```text
HUKUPUKU
├─ 고객 영역
│  ├─ 홈                         /
│  ├─ 상품
│  │  ├─ 상품 목록·검색           /products
│  │  └─ 상품 상세                /products/[slug]
│  ├─ 장바구니                    /cart
│  ├─ 체크아웃                    /checkout                  [Member]
│  └─ 주문 완료                   /orders/[orderNo]/complete [Member]
├─ 인증
│  ├─ 로그인                      /login
│  └─ 회원가입                    /signup
├─ 마이페이지                     /account                   [Member]
│  ├─ 주문 목록                   /account/orders
│  ├─ 주문 상세                   /account/orders/[orderNo]
│  └─ 프로필·배송지                /account/profile           [P1]
├─ 관리자                         /admin                     [Admin]
│  ├─ 상품 목록                   /admin/products
│  ├─ 상품 등록                   /admin/products/new
│  ├─ 상품·옵션·재고 수정          /admin/products/[productId]
│  ├─ 주문 목록                   /admin/orders
│  └─ 주문 상세·상태 변경          /admin/orders/[orderNo]
└─ 시스템
   ├─ 찾을 수 없음                not-found
   ├─ 접근 거부                    forbidden
   └─ 예기치 않은 오류             error
```

편집 컬렉션(`/collections/[slug]`)과 찜(`/account/wishlist`)은 P1이며 첫 MVP 내비게이션에는 노출하지 않습니다. `/admin`과 `/account`는 각각의 첫 유효 화면으로 이동시키며 비어 있는 대시보드를 만들지 않습니다.

## 전역 내비게이션

### 고객 헤더

| 위치 | 데스크톱 | 모바일 |
| --- | --- | --- |
| 시작 | 로고, SHOP | 메뉴 버튼, 로고 |
| 중심 | 검색 입력 | 검색 버튼 또는 확장 입력 |
| 끝 | 로그인/마이, 장바구니 수량 | 마이, 장바구니 수량 |

- 로고는 홈, `SHOP`은 전체 상품 목록으로 이동합니다.
- 로그인 전 `마이` 접근은 로그인으로 보내고 성공 후 원래 주소로 복귀합니다.
- 장바구니 수량은 서로 다른 품목 수가 아니라 담긴 총수량으로 통일합니다.
- 목록 화면에서는 모바일 필터를 시트로 열되, 선택 결과는 같은 URL 규칙을 사용합니다.

### 계정 내비게이션

- P0: 주문 내역, 로그아웃
- P1: 프로필·배송지, 찜
- 모바일에서는 페이지 상단 선택 메뉴, 데스크톱에서는 왼쪽 보조 내비게이션을 사용합니다.

### 관리자 내비게이션

- 고객 헤더와 분리된 관리자 전용 셸을 사용합니다.
- 1차 메뉴는 `상품·재고`, `주문`, `스토어로 이동`입니다.
- 현재 메뉴, 로그인한 관리자, 로그아웃을 항상 확인할 수 있어야 합니다.

## URL과 탐색 상태 규칙

상품 목록과 검색은 `/products` 한 화면을 공유합니다.

| 의미 | 쿼리 키 | 예시 |
| --- | --- | --- |
| 검색어 | `q` | `?q=linen` |
| 카테고리 | `category` | `?category=outer` |
| 브랜드 | `brand` 반복 | `?brand=atelier-n&brand=orbit` |
| 최저·최고 가격 | `minPrice`, `maxPrice` | `?minPrice=50000&maxPrice=200000` |
| 색상·사이즈 | `color`, `size` 반복 | `?color=black&size=m` |
| 정렬 | `sort` | `?sort=latest` |
| 페이지 | `page` | `?page=2` |

- 허용하지 않는 값은 무시하고 기본값으로 정규화합니다.
- 기본 정렬 `latest`와 첫 페이지는 URL에서 생략할 수 있습니다.
- 필터 변경 시 페이지는 1로 초기화합니다.
- 상품 상세에서 뒤로 가면 목록의 검색·필터·스크롤 문맥을 복원합니다.
- 보안·개인정보 값, 장바구니 내용, 체크아웃 입력은 URL에 넣지 않습니다.

## 권한과 이동 규칙

| 접근 시도 | Guest | Member | Admin |
| --- | --- | --- | --- |
| 공개 상품·장바구니 | 허용 | 허용 | 허용 |
| `/login`, `/signup` | 허용 | `/account/orders`로 이동 | `/admin/products`로 이동 |
| `/checkout` | 로그인 후 원래 주소 복귀 | 허용 | 허용하되 고객 문맥으로 동작 |
| `/account/**` | 로그인 후 원래 주소 복귀 | 본인 데이터만 허용 | 본인 고객 데이터만 허용 |
| `/admin/**` | 접근 거부 | 접근 거부 | 허용 |

- 로그인 복귀 주소는 서비스 내부의 안전한 경로만 허용합니다.
- 타인의 주문 번호 접근은 주문 존재 여부를 노출하지 않고 찾을 수 없음 또는 접근 거부로 처리합니다.
- 관리자 권한은 화면뿐 아니라 모든 서버 요청에서 다시 검사합니다.

## 핵심 사용자 흐름

### 상품 발견과 장바구니

```text
홈 → 상품 목록/검색 → 필터·정렬 → 상품 상세
→ 옵션·수량 선택 → 장바구니 담기 → 장바구니 확인
```

### Guest의 주문 전환

```text
장바구니 → 체크아웃 시도 → 로그인
→ 기존 장바구니와 복귀 주소 복원 → 체크아웃
→ 테스트 주문 완료 → 주문 상세
```

### 재고 충돌 복구

```text
체크아웃 → 서버 재검증 실패 → 부족한 옵션·가능 수량 안내
→ 장바구니로 복귀 → 수량/옵션 수정 → 다시 체크아웃
```

### 운영과 고객 상태 연결

```text
관리자 주문 목록 → 주문 상세 → 허용된 다음 상태로 변경
→ 변경 이력 기록 → 고객 주문 상세에 동일 상태 반영
```

## 경계와 소유권

- 목록 화면은 탐색 조건과 결과 표현을 소유하고, 상품 상세의 옵션 상태는 소유하지 않습니다.
- 장바구니는 예상 금액을 보여주지만 최종 가격과 재고 확정은 체크아웃 서버 흐름이 소유합니다.
- 주문 완료 화면은 성공한 주문을 조회해 보여줄 뿐 새 주문을 생성하지 않습니다.
- 관리자 화면은 고객용 상품 표현을 직접 복제하지 않고 동일한 상품·주문 도메인 규칙을 사용합니다.
- 헤더의 장바구니 수량, 로그인 상태처럼 여러 화면에서 쓰는 정보는 전역 셸이 표시하되 서버 데이터를 기준으로 갱신합니다.
