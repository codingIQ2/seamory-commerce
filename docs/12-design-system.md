# 12. HUKUPUKU 디자인 시스템

## 문서 목적

HUKUPUKU의 편집숍다운 인상과 정확한 커머스 정보를 같은 규칙으로 구현하기 위한 최소 디자인 시스템입니다. 이 문서의 토큰과 컴포넌트 상태는 5단계 기술 설계와 6단계 프로젝트 초기화에서 코드 변수로 옮깁니다.

## 디자인 방향

### 핵심 문장

> 에디토리얼의 여백 위에 구매 정보를 또렷하게 놓는다.

### 원칙

1. **상품이 가장 강한 시각 요소다.** 인터페이스 장식이 이미지와 상품명을 방해하지 않습니다.
2. **정보 밀도에 질서를 준다.** 가격, 옵션, 재고, 배송처럼 결정에 필요한 내용을 짧은 묶음으로 구분합니다.
3. **행동의 우선순위가 명확하다.** 한 영역에는 하나의 주 행동만 둡니다.
4. **상태를 숨기지 않는다.** 품절, 가격 변경, 저장 중, 오류를 텍스트와 형태로 설명합니다.
5. **고객과 관리자는 같은 언어를 쓰되 다른 밀도를 갖는다.** 고객 화면은 이미지 중심, 관리자 화면은 데이터 중심입니다.

## 색상 토큰

초안의 Signal Red와 Cobalt를 작은 본문과 버튼에서도 사용할 수 있도록 더 어두운 접근성 색상으로 조정했습니다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `color.ink` | `#171717` | 기본 본문, 기본 아이콘, 주요 버튼 배경 |
| `color.paper` | `#F5F2EC` | 브랜드 기본 배경 |
| `color.surface` | `#FFFDF9` | 카드, 입력, 떠 있는 영역 |
| `color.muted` | `#66625C` | 보조 설명, 메타데이터 |
| `color.mist` | `#DDE1E6` | 구분선, 비활성 배경, 스켈레톤 |
| `color.signal` | `#B8322C` | 할인, 오류, 중요한 상태 |
| `color.cobalt` | `#2447C6` | 링크, 포커스, 편집 콘텐츠 포인트 |
| `color.success` | `#247A4B` | 저장·처리 성공 상태 |
| `color.warning` | `#8A5A00` | 재고 부족, 확인이 필요한 변경 |
| `color.white` | `#FFFFFF` | 어두운 버튼 위 텍스트 |

### 검증된 기본 대비

| 조합 | 명암비 | 사용 판단 |
| --- | ---: | --- |
| Ink / Paper | 16.05:1 | 일반·큰 텍스트 사용 가능 |
| Muted / Paper | 5.42:1 | 일반 텍스트 사용 가능 |
| Signal / Paper | 5.32:1 | 일반 텍스트 사용 가능 |
| White / Signal | 5.95:1 | 버튼 텍스트 사용 가능 |
| Cobalt / Paper | 6.73:1 | 링크 텍스트 사용 가능 |
| White / Cobalt | 7.52:1 | 버튼 텍스트 사용 가능 |

- 대비 수치는 sRGB 상대 휘도 계산 기준이며 실제 구현 후 자동 접근성 검사로 다시 확인합니다.
- `Mist`는 경계와 배경용이며 텍스트 색으로 사용하지 않습니다.
- 성공·경고·오류는 아이콘, 제목, 설명을 함께 사용해 색상에만 의존하지 않습니다.

## 타이포그래피

### 글꼴

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `font.sans` | `Pretendard Variable`, `Pretendard`, `Inter`, system-ui, sans-serif | 한글·영문 본문과 UI |
| `font.display` | `Arial Black`, `Pretendard`, sans-serif | 영문 워드마크와 짧은 캠페인 제목 |
| `font.mono` | `ui-monospace`, `SFMono-Regular`, Consolas, monospace | SKU, 주문 번호, 관리자 기술 값 |

- 웹폰트가 늦게 로드되어도 레이아웃이 크게 흔들리지 않도록 시스템 폴백을 둡니다.
- 장문의 한글에 디스플레이 글꼴을 사용하지 않습니다.
- 가격과 수량은 가능하면 고정폭 숫자 기능을 사용합니다.

### 크기와 행간

| 토큰 | 크기 / 행간 | 용도 |
| --- | --- | --- |
| `text.xs` | 12 / 18px | 보조 라벨, 상태 메타데이터 |
| `text.sm` | 14 / 21px | 상품 카드, 관리자 보조 정보 |
| `text.md` | 16 / 24px | 기본 본문, 입력, 버튼 |
| `text.lg` | 20 / 28px | 섹션 소제목, 상품 가격 |
| `text.xl` | 24 / 32px | 모바일 페이지 제목 |
| `text.2xl` | 32 / 40px | 데스크톱 페이지 제목 |
| `text.3xl` | 48 / 52px | 에디토리얼 제목 |
| `text.hero` | 72 / 72px | 넓은 화면의 짧은 히어로 제목 |

- 모바일에서 `text.hero`는 40 / 44px로 축소합니다.
- 본문 기본 굵기는 400, 강조 600, 워드마크와 짧은 디스플레이만 700~900을 사용합니다.
- 버튼과 탭에 전부 대문자를 강제하지 않습니다. 영문 섹션 라벨만 선택적으로 사용합니다.

- 관리자 폼은 읽기 폭을 제한하되 옵션·재고 표는 남은 폭을 사용합니다.

## 형태와 효과

| 토큰 | 값 | 원칙 |
| --- | --- | --- |
| `radius.none` | 0 | 이미지, 에디토리얼 영역 |
| `radius.sm` | 4px | 입력, 버튼, 카드의 최소 모서리 |
| `radius.pill` | 999px | 필터 칩, 작은 상태 배지 |
| `border.default` | 1px solid `color.mist` | 기본 구분 |
| `border.strong` | 1px solid `color.ink` | 선택·강조 구분 |
| `shadow.overlay` | `0 12px 32px rgba(23,23,23,.16)` | 모달·시트만 사용 |

- 상품 카드에 기본 그림자를 사용하지 않습니다.
- 구분선, 여백, 글자 굵기로 계층을 먼저 표현합니다.

## 아이콘

- 2px 선 굵기의 단순한 라인 아이콘을 사용합니다.
- 기본 20px, 단독 터치 행동은 24px 아이콘을 44px 이상의 버튼 안에 넣습니다.
- 검색, 계정, 장바구니, 닫기, 펼치기처럼 익숙한 기능에만 아이콘 단독 사용을 허용합니다.
- 관리자 위험 행동과 상태는 아이콘 옆에 텍스트 라벨을 반드시 표시합니다.
- 이모지를 기능 아이콘으로 사용하지 않습니다.

## 핵심 컴포넌트

### Button

| 종류 | 표현 | 사용 |
| --- | --- | --- |
| Primary | Ink 배경 + White 텍스트 | 담기, 주문, 저장 등 영역의 주 행동 |
| Secondary | 투명 배경 + Ink 테두리 | 쇼핑 계속, 미리보기, 취소 |
| Editorial | Cobalt 텍스트 + 밑줄/화살표 | 컬렉션과 콘텐츠 이동 |
| Destructive | Signal 배경 또는 텍스트 | 삭제·취소처럼 되돌리기 어려운 행동 |

상태는 `default`, `hover`, `focus-visible`, `pressed`, `disabled`, `loading`을 구현합니다.

- 최소 높이 44px, 좌우 여백 16px 이상
- 로딩 시 크기를 유지하고 동작을 중복 실행하지 않음
- 비활성만으로 이유를 숨기지 않고 가까운 위치에 조건을 안내
- 한 영역에서 Primary 버튼을 여러 개 경쟁시키지 않음

### Text field와 Select

- 라벨을 입력 위에 항상 표시하고 placeholder를 라벨 대신 사용하지 않습니다.
- 기본 높이 48px, 관리자 밀집 표 안에서는 40px까지 허용합니다.
- 오류는 테두리, 오류 아이콘, 문구, `aria-describedby` 연결로 전달합니다.
- 도움말과 오류가 동시에 필요하면 오류를 더 가까이 배치합니다.
- 검색 입력은 제출 버튼 또는 Enter 동작을 제공하고 지우기 버튼에는 접근 가능한 이름을 둡니다.

### Filter chip

- 선택 조건명과 제거 아이콘을 함께 표시합니다.
- 높이 36px, `radius.pill`, 키보드로 제거할 수 있어야 합니다.
- `필터 2`처럼 개수만 보일 때도 시트 안에서 선택 내용을 확인할 수 있어야 합니다.

### Product card

```text
┌────────────────────┐
│ 4:5 상품 이미지     │  이미지 전체가 상세 링크
│ [품절/신상품 배지]   │
└────────────────────┘
BRAND                  text.xs / 600
상품명                 text.sm / 400, 최대 2줄
129,000원              text.md / 600
20%  103,200원         Signal + Ink
```

- 기본 카드에 버튼과 정보를 과도하게 넣지 않습니다.
- 품절 상품도 탐색 맥락을 위해 표시하되 텍스트 상태를 제공합니다.
- 할인율과 판매가는 의미 순서가 스크린리더에서도 유지되게 구성합니다.

### Price block

- 정가, 할인, 판매가의 관계가 문장 순서로 이해되어야 합니다.
- 취소선만으로 할인 전 가격 의미를 전달하지 않습니다.
- 원화는 `158,400원`처럼 천 단위 구분과 통화 단위를 표시합니다.
- 관리자 입력값은 표시 형식과 저장 형식을 분리하고 원 단위 정수로 검증합니다.

### Option selector

- 색상과 사이즈를 단계적으로 보여주되 최종 선택은 하나의 SKU를 가리킵니다.
- 선택, 선택 가능, 품절, 포커스 상태를 형태와 텍스트로 구분합니다.
- 품절 옵션은 비활성화하되 왜 선택되지 않는지 접근성 이름에 포함합니다.

### Quantity stepper

- `감소`, 현재 수량, `증가`의 세 영역을 각각 44px 이상으로 제공합니다.
- 입력 가능한 최솟값·최댓값과 재고 한도를 서버 검증 결과에 맞춰 안내합니다.
- 수량 변경 후 항목 소계와 전체 금액 갱신 상태를 전달합니다.

### Status badge와 Timeline

- Badge는 짧은 현재 상태, Timeline은 주문 처리 순서와 이력에 사용합니다.
- 상태명은 고객용 한글과 내부 코드가 분리됩니다. 예: `PREPARING` → `상품 준비 중`.
- 현재·완료·예정·취소를 색상만이 아니라 라벨과 아이콘 형태로 구분합니다.

### Alert

| 수준 | 예시 | 구성 |
| --- | --- | --- |
| Info | 테스트 결제 안내 | 제목 또는 문장 + 필요 시 링크 |
| Success | 장바구니 담기, 저장 성공 | 결과 + 다음 행동 |
| Warning | 가격 변경, 낮은 재고 | 원인 + 영향을 받는 항목 + 수정 행동 |
| Error | 주문 실패, 서버 오류 | 실패 내용 + 사용자가 할 수 있는 행동 + 추적 ID(시스템 오류) |

- 토스트는 짧은 성공 피드백에만 사용하고 복구가 필요한 오류는 화면에 유지합니다.
- 자동으로 사라지는 메시지는 중요한 정보를 담지 않습니다.

### Modal과 Mobile sheet

- Modal은 삭제·주문 취소·상태 변경 확인처럼 짧고 중요한 결정에 사용합니다.
- 모바일 필터처럼 긴 탐색 UI는 하단 또는 전체 높이 Sheet를 사용합니다.
- 열릴 때 첫 의미 있는 요소로 초점을 이동하고 닫은 뒤 실행 버튼으로 돌려보냅니다.
- 배경 스크롤을 막고 Escape와 명시적 닫기 버튼을 모두 지원합니다.

### Admin table

- 열 제목, 정렬 방향, 행별 행동을 텍스트로 식별할 수 있어야 합니다.
- 모바일에서는 핵심 열을 카드로 재구성하고 데이터 의미가 사라지는 가로 잘라내기를 하지 않습니다.
- 대량 수정은 MVP에서 제외하고 한 번의 변경 대상을 명확히 보여줍니다.

## 콘텐츠 규칙

| 상황 | 권장 | 피함 |
| --- | --- | --- |
| 버튼 | `장바구니에 담기`, `변경 저장` | `확인`, `진행`처럼 결과가 모호한 표현 |
| 품절 | `M 사이즈가 품절되었습니다` | `불가`, 색상만 붉게 표시 |
| 빈 결과 | `조건에 맞는 상품이 없습니다` + 초기화 | 빈 그리드만 표시 |
| 주문 처리 | `주문을 처리하고 있습니다` | 성공 전 `주문 완료` |
| 시스템 오류 | `잠시 후 다시 시도해 주세요` + 추적 ID | 내부 예외·DB 정보 노출 |

- 브랜드 말투는 짧고 차분하게 유지하며 구매를 과도하게 재촉하지 않습니다.
- 실제 제휴, 최저가, 배송 보장을 암시하는 샘플 문구를 사용하지 않습니다.

## 포커스와 상호작용

- 모든 상호작용 요소는 `focus-visible`에서 2px Cobalt 링과 2px 여백을 표시합니다.
- 논리적인 DOM 순서와 시각 순서를 일치시킵니다.
- 헤더 다음에 본문으로 이동하는 건너뛰기 링크를 둡니다.
- 터치 대상은 최소 44×44px이며 인접 대상 사이에 충분한 간격을 둡니다.
- Hover에서만 제공하는 정보나 행동을 만들지 않습니다.
- 필터 적용, 장바구니 갱신, 주문 상태 변경 결과는 필요한 경우 라이브 영역으로 알립니다.

## 움직임

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `motion.fast` | 120ms | 버튼·칩의 즉각적인 상태 변화 |
| `motion.base` | 200ms | 메뉴, 드롭다운, 작은 전환 |
| `motion.slow` | 320ms | 모바일 시트와 모달 |

- 기본 easing은 `cubic-bezier(.2, 0, 0, 1)`을 사용합니다.
- `prefers-reduced-motion`에서는 이동 애니메이션을 제거하고 불투명도 변화도 최소화합니다.
- 주문·저장 성공을 애니메이션으로만 전달하지 않습니다.

## 이미지 규칙

- 상품 목록은 4:5, 상세 대표 이미지는 원본 비율을 보존하되 영역의 최대 크기를 제한합니다.
- 실제 브랜드 이미지를 복제하지 않고 자체 제작 또는 사용 허가된 포트폴리오 이미지를 사용합니다.
- 상품 이미지 대체 텍스트는 상품명과 구분되는 시점·색상·형태 정보를 필요할 때만 추가합니다.
- 장식적인 에디토리얼 이미지는 빈 대체 텍스트를 사용할 수 있습니다.
- 이미지가 없거나 실패해도 상품명과 가격, 행동이 유지되어야 합니다.

## 구현 토큰 이름

```text
--color-ink, --color-paper, --color-surface, --color-muted
--color-mist, --color-signal, --color-cobalt
--space-1 ... --space-9
--text-xs ... --text-hero
--radius-sm, --radius-pill
--layout-max, --layout-reading
--motion-fast, --motion-base, --motion-slow
```

- 의미 토큰(`--color-text`, `--color-action`, `--color-error`)이 원시 팔레트 토큰을 참조하게 합니다.
- 컴포넌트 안에서 임의의 색상·간격 값을 반복하지 않습니다.
- 다크 모드는 MVP에서 제외하지만 의미 토큰 구조는 이후 테마 확장이 가능하게 유지합니다.
