# 01. 제품 정의서

## 한 문장 정의

HUKUPUKU는 사용자가 여러 패션 브랜드의 상품을 자신의 취향에 따라 발견하고, 비교하고, 안심하고 구매할 수 있게 돕는 멀티브랜드 커머스입니다.

## 배경

대형 패션 플랫폼에는 선택지가 많지만, 상품 수가 늘수록 탐색 피로도도 커집니다. 사용자는 마음에 드는 스타일을 빠르게 좁히고 싶어 하며, 구매 직전에는 가격·옵션·재고·배송 정보를 명확하게 확인하고 싶어 합니다. 판매 운영자는 상품과 주문의 상태를 안전하고 일관되게 관리해야 합니다.

## 목표 사용자

### 1차 사용자 — 탐색형 구매자

- 20~30대, 모바일 쇼핑에 익숙함
- 특정 상품보다 새로운 브랜드와 코디를 발견하는 과정도 중요하게 생각함
- 할인율뿐 아니라 핏, 소재, 리뷰, 배송 조건을 비교함

### 2차 사용자 — 목적형 구매자

- 원하는 카테고리와 조건이 분명함
- 검색·필터·정렬의 정확성과 빠른 결제를 중요하게 생각함

### 운영 사용자 — 스토어 관리자

- 상품, 옵션, 재고, 프로모션, 주문 상태를 관리함
- 실수를 줄이는 명확한 상태와 변경 이력이 필요함

## 핵심 사용자 문제

1. 수많은 상품 가운데 내 취향에 맞는 상품을 찾기 어렵다.
2. 상품 간 조건을 비교하는 데 시간이 오래 걸린다.
3. 옵션 품절이나 배송 조건을 구매 직전에 알게 된다.
4. 포트폴리오형 쇼핑몰에서는 주문 이후의 운영 흐름이 생략되는 경우가 많다.

## 제품 원칙

- **Discoverable**: 첫 화면부터 취향에 맞는 탐색 경로를 제공합니다.
- **Comparable**: 구매 결정에 필요한 정보를 같은 기준으로 보여줍니다.
- **Trustworthy**: 가격, 재고, 주문 상태가 서버 기준으로 일관되게 동작합니다.
- **Operable**: 고객 기능과 관리자 기능이 하나의 데이터 흐름으로 연결됩니다.
- **Accessible**: 키보드 조작, 명확한 레이블, 충분한 대비를 기본 품질로 봅니다.

## 핵심 사용자 여정

```text
유입 → 컬렉션/검색 탐색 → 필터·정렬 → 상품 상세
    → 옵션 선택 → 장바구니 → 주문/결제 → 주문 상태 확인
```

운영자 여정은 다음과 같습니다.

```text
상품 등록 → 옵션·재고 설정 → 판매 상태 관리
        → 주문 확인 → 처리 상태 변경 → 고객 화면 반영
```

## MVP에 포함하지 않는 것

- 실제 판매자 정산과 입점 계약
- 복잡한 추천 AI와 개인화 모델
- 해외 배송·다국가 세금 계산
- 라이브 커머스와 커뮤니티 피드
- 실제 운영 결제 승인 및 환불 자동화

이 기능들은 핵심 구매 흐름이 안정된 이후의 확장 범위로 남깁니다.

## 핵심 가설

- 스타일 태그와 큐레이션을 함께 제공하면 단순 카테고리 탐색보다 상품 발견이 쉬워질 것입니다.
- 상품 카드와 상세 화면의 정보 기준을 통일하면 구매 전 이탈을 줄일 수 있습니다.
- 재고와 주문 상태를 관리자 화면까지 연결하면 포트폴리오의 실무 설득력이 높아질 것입니다.
